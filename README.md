# code-atlas

파이썬 레포의 패키지·모듈·클래스·함수를 노드로, 호출·사용·상속 관계를 선으로 그려 보여 주는 로컬 탐색기다. 레포를 모든 폴더를 접은 채로 열고, 파일이나 함수를 고르면 그 노드에서 나가는 흐름만 펼쳐 그리며, 그래프 위에 떠 있는 정보 패널이 고른 노드의 위치·요약·코드를 보여 준다. 구조는 `ast`로 읽고, 호출 대상은 basedpyright 언어 서버에 정의 위치를 물어 확인한다.

설계 문서는 vault `personal/projects/code-atlas/docs/`에 있다.

## 설치

Python 3.12 이상과 Node.js(npm)가 필요하다. macOS와 Linux에서 쓴다.

```bash
python3 -m venv .venv
.venv/bin/pip install -e .
cd frontend && npm install && npm run build
```

basedpyright는 Python 의존성으로 함께 설치한다. 화면은 `frontend/dist/`를 백엔드가 같은 포트에서 서빙하므로 처음 한 번과 `frontend/src`를 고친 뒤에 `npm run build`를 실행한다. 백엔드는 이 폴더의 `frontend/dist/`를 읽으므로 `pip install`에 `-e`를 붙인다.

## 실행

```bash
.venv/bin/code-atlas <레포 경로> [--python PATH] [--port 8766] [--no-open] [--no-cache] [--style-guide PATH]
.venv/bin/code-atlas analyze <레포 경로> [--python PATH] [--json] [--no-cache]
```

`code-atlas <레포 경로>`는 `http://127.0.0.1:8766`에 서버를 띄워 브라우저를 열고 레포를 분석한다. 분석하는 동안 화면은 단계 이름과 진행 수(`호출 대상 확인 12,000 / 16,617`)를 적은 진행 표시를 보이고, 분석이 끝나면 그래프를 그린다. 분석하지 못하면 화면에 까닭과 `다시 분석` 버튼을 보인다. 분석이 끝나면 터미널에 `노드 695 · 선 1417 · 지점 4680 · 호출 해석률 87.2% (2043/2342) · 6033ms` 같은 줄을 한 번 출력한다. 언어 서버가 시간 안에 답하지 못한 지점이 있으면 `정의 요청 N개가 시간 안에 응답받지 못했다`를 표준 오류에 적고, 화면의 필터 창 레포 정보에 `응답 없음 N`을 붙인다. `code-atlas analyze`는 서버를 띄우지 않고 같은 줄과 `미사용 후보 4개` 줄을 출력하며, `--json`을 주면 두 줄 대신 분석 결과 전체를 JSON으로 출력한다. JSON에는 미사용 후보가 들지 않는다.

| 옵션 | 뜻 |
|---|---|
| `--python PATH` | 대상 레포의 파이썬 인터프리터. 실행 파일 경로나 `PATH`에 있는 이름을 준다 |
| `--port PORT` | 서버 포트. 기본값은 8766이고, 이미 쓰는 포트면 안내를 적고 끝난다 |
| `--no-open` | 브라우저를 열지 않고 주소만 출력한다. `DISPLAY`가 없는 Linux에서는 옵션 없이도 주소만 출력한다 |
| `--no-cache` | 저장해 둔 분석 결과를 읽지 않고 레포 전체를 다시 분석해 덮어쓴다 |
| `--style-guide PATH` | LLM 요약의 문체를 정하는 서술 규약 문서 |

서버는 `127.0.0.1`에만 열린다. `Ctrl+C`를 한 번 누르면 분석 중에도 서버와 언어 서버 프로세스를 함께 끝낸다.

### 대상 레포의 인터프리터

basedpyright가 대상 레포의 외부 패키지 import를 해석하려면 그 레포의 파이썬 인터프리터가 필요하다. `--python`을 주지 않으면 레포 루트에서 `.venv/bin/python`, `venv/bin/python`, poetry 환경(`poetry.lock`이 있고 `poetry`가 설치돼 있을 때 `poetry env info -p`가 알려 준 환경) 순서로 찾는다. 찾지 못하면 `<레포>에서 가상환경을 찾지 못했다. --python으로 인터프리터 경로를 지정한다.`를 적고 종료 코드 2로 끝나므로, 인터프리터를 직접 지정한다.

```bash
.venv/bin/code-atlas ~/work/some-repo --python ~/work/some-repo/env/bin/python
.venv/bin/code-atlas ~/work/some-repo --python python3
```

`--python`에 준 경로를 실행할 수 없을 때도 안내를 적고 종료 코드 2로 끝난다. 가상환경이 없는 레포에 시스템 인터프리터를 지정하면 그 인터프리터에 설치되지 않은 외부 패키지의 import와 그 패키지 객체를 거친 호출은 대상을 확인하지 못해 미확인 호출로 셀 수 있다. 레포 안의 함수·클래스 사이 관계는 그대로 분석한다. code-atlas는 대상 레포에 파일을 쓰지 않는다.

### 분석 캐시

분석 결과는 레포 경로마다 `~/.cache/code-atlas/analysis-{레포 경로의 해시}.db` 파일 하나에 저장한다. 파일마다의 구조 추출 결과는 파일 경로와 본문 해시로, 호출 지점의 판정은 환경 지문과 함께 담는다. 다시 열면 본문이 바뀐 파일의 지점과 그 파일의 정의를 가리키는 지점, 그 파일을 import로 따라 들여오는 파일의 지점 가운데 판정이 레포 안이거나 미확인인 지점과 판정이 외부·내장이어도 레포 안 정의로 바뀔 수 있는 지점만 언어 서버에 다시 묻는다. 바뀐 파일이 없으면 언어 서버에 묻지 않고 그래프를 내고, 언어 서버는 그래프를 낸 뒤에 띄운다. 바뀐 파일이 있으면 저장해 둔 판정으로 조립한 그래프를 먼저 그리고 다시 물은 뒤의 그래프로 한 번 더 바꾼다.

- **판정을 버리는 조건**: 환경 지문이 달라지면 저장한 판정을 쓰지 않고 모든 지점을 다시 묻는다. 환경 지문은 basedpyright 버전, 인터프리터의 실제 경로와 버전, `sys.path`의 폴더마다 설치된 패키지 이름 목록, 소스 루트, `pyproject.toml`의 `[tool.pytest.ini_options].pythonpath`를 해시한 값이다. 레포를 열어 둔 채 가상환경에 패키지를 설치하거나 지웠으면 "새로고침"이 언어 서버를 새로 띄워 모든 지점을 다시 묻는다. code-atlas의 분석 규칙이나 저장 형식의 판 번호가 달라지면 그 파일의 내용을 비운다. 깨진 캐시 파일은 지우고 새로 분석한다.
- **캐시가 반영하지 못하는 변경**: 판정이 내장·외부인 지점은 바뀐 파일을 import로 따라 들여오는 파일에서 세 경우에만 다시 묻는다. 물을 위치의 이름이 바뀐 파일과 그 파일이 import로 따라 들여오는 파일이 정의한 이름이거나 바뀐 파일이 `from … import`로 가져오는 이름인 지점(`as`로 그 이름에 묶은 이름 포함), 외부 클래스를 상속하는 지점, 레포 모듈에서 가져오는 import 지점이다. 그래프의 노드 목록과 선은 `--no-cache`로 분석한 결과와 같고, 선을 만들지 않는 호출 지점의 판정이 남는 경우가 두 가지 있다. 고친 함수의 반환 타입이 달라져 다른 파일의 메서드 호출이 내장·외부에서 미확인으로 바뀌는 경우와, 외부 이름을 재내보내던 import 문이나 파일을 지운 경우다. 두 경우에 그 호출이 든 함수의 `미확인 호출 N곳`과 미사용 후보가 `--no-cache` 결과와 다를 수 있다.
- **지우기**: `rm ~/.cache/code-atlas/analysis-*.db`. 같은 폴더의 `summaries.db`는 LLM 요약의 캐시다.

### 화면 조작

| 동작 | 결과 |
|---|---|
| 파일 상자나 파일트리의 파일 클릭 | 그 파일을 펼침 단계로 열어 파일 밖과 이어진 함수·클래스와 `안쪽 k개` 손잡이를 그리고 파일 단위 흐름을 보여 준다. 정보 패널의 코드 뷰어에 그 파일의 전체 코드를 연다 |
| 펼친 파일 상자의 손잡이(`안쪽 k개`) 클릭 | 그 파일 안에서만 쓰이는 정의까지 모두 그린다. 손잡이가 `안쪽 k개 접기`로 바뀌고 다시 누르면 펼침 단계로 돌아간다 |
| 함수·클래스 클릭 | 그 노드에서 나가는 흐름을 필터 창의 "흐름 단계"(1~3, 기본 2)만큼 펼친다. 정보 패널의 코드 뷰어에 그 노드가 든 파일의 전체 코드를 열어 정의의 첫 줄을 맨 위에 두고, 정의 밖의 줄은 회색으로 흐리게 그린다 |
| 함수 더블클릭 | 그 함수를 호출하는 함수와 그 함수가 호출하는 함수만 보여 주는 함수 시점 뷰로 들어간다 |
| 접힌 폴더 상자 클릭 | 폴더를 한 단계 펼친다. 안의 파일 상자와 하위 폴더 상자가 모두 폴더 영역 안에 나온다 |
| 펼친 폴더 영역의 머리 줄(폴더 경로가 적힌 줄) 클릭 | 그 폴더를 접는다. 영역의 빈 곳은 그래프 바탕과 같아 눌러도 접히지 않는다 |
| 파일트리의 폴더 행 클릭 | 폴더를 펼치거나 접는다 |
| 노드에 마우스 올리기 | 흐리게 그린 노드도 올린 동안 가장 진한 단계로 그리고 이름과 종류를 말풍선에 적는다 |
| 배지·줄 수 숫자·진입점 표시에 마우스 올리기 | 그 배지의 뜻과 값을 말풍선에 적는다(접힌 파일 상자의 `21`은 안에 든 함수·클래스 21개) |
| 선에 마우스 올리기 | 커서 밑을 지나는 선을 가장 진한 단계로 다른 선 위에 그리고 선마다 출발·도착 노드와 관계 수를 말풍선에 한 줄씩 적는다. 줄기에 든 선에는 그 선의 관계 수를 선 위에 적는다 |
| 선 클릭 | 그 선의 도착 노드를 클릭한 것처럼 고른다. 도착 노드가 접힌 폴더 상자면 그 폴더를 펼친다. 커서 밑의 선이 여럿이고 도착 노드가 다르면 누른 곳에 선 목록을 고정하고, 목록에서 고른 선의 도착 노드를 고른다 |
| 선 `Shift`+클릭 | 정보 패널에 관계가 일어난 코드 줄 목록을 띄운다. 목록의 줄을 누르면 코드 뷰어가 그 파일의 전체 코드에서 그 줄을 칠해 가운데에 보인다. 도착 노드가 같은 선이 여럿이면 그 노드로 들어오는 선 전체의 목록을 출발 노드별로 묶어 띄운다 |
| 코드 뷰어의 이름 `Mod`+클릭 | 그 이름의 정의가 레포 안의 함수·클래스면 그 노드를 그래프에서 누른 것처럼 고르고 코드 뷰어가 그 정의로 바뀐다. `Mod`를 누른 채 올리면 이동할 수 있는 이름에 밑줄이 보이고, 레포 밖의 이름은 외부 모듈 이름을 말풍선에 적는다 |
| 코드 뷰어에서 줄 범위 끌어 고르기 | 고른 끝에 "요약 생성" 버튼을 띄운다. 누르면 그 범위의 LLM 설명을 만든다 |
| 미니맵 클릭·끌기 | 확대 비율을 그대로 둔 채 그 위치로 화면을 옮긴다 |
| 그래프 바탕 클릭, `Esc` | 선택을 푼다. `Esc`는 고정한 선 목록이 있으면 그 목록을, `배치 계산 중` 표시가 떠 있으면 그 배치를 먼저 닫거나 취소한다 |
| 왼쪽 아래 경로 찾기 버튼 | 경로 탐색 창을 펴거나 접는다. 출발 칸과 도착 칸에서 파일·클래스·함수를 검색해 고르면 두 곳을 잇는 실행 경로를 찾는다 |
| 경로 탐색 창의 숫자 버튼 | 그 번호의 경로만 굵은 선으로 강조하고 단계 목록을 그 경로로 바꾼 뒤 출발 노드를 보인다 |
| 경로 탐색 창의 단계 클릭 | 그 단계의 노드를 정보 패널에 보이고 그 노드와 다음 걸음의 노드가 보이게 화면을 옮긴다 |
| 경로 탐색 창의 `경로 전체 보기` | 경로 위 노드가 모두 보이게 화면을 맞춘다. 경로 고정 중의 "화면 맞춤"과 같다 |
| 경로 탐색 창의 `끄기` | 경로 고정을 풀고 고정 전의 선택과 펼침으로 돌아간다 |
| 상단 줄의 필터 버튼 | 필터 창을 연다. 보기 설정 구역에서 흐름 단계, 분석 덮개("없음", "순환 의존", "미사용 후보"), 테스트 코드, 외부 노드, 자동 요약을 바꾸고, 레포 정보 구역에서 파일·노드·선 수, 호출 확인 비율, 브랜치, 진입점 목록을 본다. 진입점 이름을 누르면 그 노드를 고른다. 창 밖을 누르거나 `Esc`, 필터 버튼을 누르면 닫힌다 |
| 상단 줄의 "새로고침" | 바뀐 파일만 다시 분석해 그래프를 바꾸고 보기 설정, 선택, 탐색 이력, 펼친 폴더, 경로 고정, 파일트리 검색어, 화면 위치를 레포를 처음 연 상태로 되돌린다. 화면 색, 정보 패널의 위치와 크기, 미니맵·범례의 접힘은 그대로다 |
| `Mod+P`, `Mod+K` | 파일·클래스·함수 이름으로 검색한다 |
| `Alt+←`, `Alt+→` | 탐색 이력을 뒤로, 앞으로 옮긴다. macOS에서는 `Cmd+[`·`Cmd+]`도 쓴다 |

`Mod`는 macOS에서 `Cmd`, 그 밖에서 `Ctrl`이다. 상단 줄 오른쪽에는 필터 버튼, "화면 맞춤", 화면 색 버튼, "새로고침"이 있다. 필터 버튼은 기본값(흐름 단계 2, 덮개 없음, 토글 꺼짐)과 다른 보기 설정의 수를 적고 마우스를 올리면 그 이름을 보인다. 필터 창의 토글로 테스트 코드와 외부 모듈 노드를 켜고, 왼쪽 아래 둥근 버튼 세 개로 미니맵과 범례, 경로 탐색 창을 접고 편다. 미니맵은 전체 그래프의 축소 그림 위에 지금 화면에 보이는 영역을 사각형으로 그리고, 처음에 펼친 채로 연다. 펼친 세 칸은 아래 끝을 맞춰 나란히 놓이고 폭이 모자라면 오른쪽 칸부터 위로 올라가며, 정보 패널과 겹치면 정보 패널 위에 그린다. 노드를 고르거나 경로의 단계를 누르면 화면은 확대 비율을 줄이지 않은 채 그 노드를 정보 패널과 왼쪽 아래 칸이 가리지 않는 영역으로 옮긴다. "화면 맞춤"은 그래프 전체를 정보 패널이 가리지 않는 영역에 맞추고, 경로 고정 중에는 경로 위 노드를 정보 패널과 왼쪽 아래 칸이 가리지 않는 영역에 맞춘다. 정보 패널은 처음에 그래프 영역의 오른쪽 끝에 영역 폭의 30%(최소 260px), 영역 높이 전체로 놓인다. 머리 줄을 끌어 옮기고 가장자리를 끌어 크기를 바꾸며, LLM 요약 칸과 코드 뷰어 사이의 경계선을 위아래로 끌어 두 영역의 높이를 바꾼다. 머리 줄을 더블클릭하면 패널이 기본 위치와 크기로, 요약 칸이 기본 높이로 돌아간다.

### 처음 화면과 펼침

레포는 모든 폴더를 접은 채로 열린다. 소스 루트부터 내려가며 그 층에 보이는 상자가 폴더 하나뿐인 동안에는 그 폴더를 펼쳐 연다. 폴더는 접힘과 펼침 두 단계이고, 파일 상자는 세 단계다.

- **접힘**: 상자 하나로 그린다. 오른쪽 위 배지는 안에 든 것의 수다(파일 상자는 함수·클래스 수, 폴더 상자는 파일 수).
- **펼침**: 파일을 고르거나 그 안의 함수·클래스를 고르면 그 파일 상자가 파일 밖과 선을 주고받는 정의와 진입점만 그리고, 나머지를 첫 열 맨 아래의 `안쪽 k개` 손잡이에 묶는다. 함수를 고르면 그 함수의 흐름에 든 안쪽 정의가 손잡이에서 나와 그려진다. 미사용 덮개를 켜면 손잡이에 든 미사용 후보도 그려진다. 안쪽 정의가 하나뿐이거나 파일 밖과 선을 주고받는 정의가 하나도 없으면 손잡이 없이 모두 그린다.
- **전부**: 손잡이를 누르면 모든 정의를 그린다. 펼침 단계에서 보이던 정의의 열과 위아래 순서는 그대로다.

대상을 확인하지 못한 호출의 수는 정보 패널 머리 줄에 `미확인 호출 N곳`으로 적는다. 레포를 연 처음 화면과 "화면 맞춤"을 누른 화면은 전체 맞춤 상태다. 전체 맞춤 상태에서는 폴더를 펼치거나 접을 때, 손잡이를 누를 때, 테스트 코드·외부 노드 토글과 덮개를 바꿀 때처럼 배치가 바뀔 때마다 화면을 다시 맞춘다. 처음 화면과 이 맞춤은 이름표가 읽히는 확대 비율(80%) 아래로 줄이지 않는다. 그래프 전체가 80%~100%에서 정보 패널이 가리지 않는 영역에 들어오면 전체를 맞추고, 들어오지 않으면 확대 비율을 80%에 두고 방금 펼치거나 접은 상자의 왼쪽 위(그런 상자가 없으면 그래프의 왼쪽 위)를 그 영역의 왼쪽 위에 놓는다. 나머지는 화면을 끌거나 미니맵으로 본다. "화면 맞춤" 버튼은 확대 비율을 줄여서라도 그래프 전체를 맞춘다. 화면을 끌거나 확대·축소하거나 미니맵으로 옮기거나 노드를 골라 화면이 그 노드로 옮겨지면 전체 맞춤 상태가 꺼진다. 꺼진 뒤에는 확대 비율을 그대로 두고, 펼치거나 접은 상자의 왼쪽 위 모서리를 화면의 같은 좌표에 붙잡는다. 그 모서리가 정보 패널과 왼쪽 아래 칸이 가리지 않는 영역 밖이면 영역 안으로 들어올 만큼만 화면을 옮긴다. 배치 계산이 배치 움직임 시간(0.3초)보다 길어지면 앞의 그래프를 그대로 둔 채 그래프 위쪽에 `배치 계산 중 · Esc로 취소`를 띄우고, `Esc`를 누르면 계산을 버리고 그 조작 전의 화면으로 돌아간다.

### 선

- **합류**: 자식을 그리지 않는 노드(접힌 상자, 함수·클래스, 외부 노드)로 들어오는 선은 그 노드의 왼쪽 변 앞에서 한 줄기로 합쳐져 화살촉 하나로 들어간다. 선이 줄기에 붙는 곳에는 점을 찍는다. 나가는 쪽은 합치지 않는다.
- **숫자**: 늘 보이는 숫자는 도착 노드 앞의 화살촉 앞에 적는 수 하나이고, 그 노드로 들어오는 관계(호출·사용·상속이 일어난 코드 지점)의 합계다. 합계가 1이면 적지 않는다. 줄기에 든 선 하나의 관계 수는 그 선에 마우스를 올리거나 그 선에 닿는 노드를 고르거나 그 선이 경로의 걸음일 때 그 선 위에 적는다.
- **겹친 구간**: 여러 선이 함께 지나는 구간에서는 커서 밑을 지나는 선만 강조하고 말풍선에 선마다 한 줄씩 적는다. 도착 노드가 모두 같으면 첫 줄에 `노드 N개 → 이름 · M곳`을 적고 누르면 그 노드를 고른다. 도착 노드가 다르면 누른 곳에 선 목록을 고정하고, 목록의 줄에 올리면 그 선 하나를 강조하며 누르면 그 선의 도착 노드를 고른다. 목록은 `Esc`, 목록 밖 클릭, 다른 선 클릭으로 닫힌다.
- **경로**: 선은 자기 출발·도착 노드와 그 조상이 아닌 상자의 안을 지나지 않는다. 펼친 폴더 영역 안의 파일로 들어가는 선은 상자 사이의 빈 가로 줄과 열 앞 통로로 돌아간다.

### 새로고침과 변경 감지

화면은 창이 보이는 동안 2초마다 서버에 분석 상태를 묻고, 서버는 마지막 분석 뒤 내용이 바뀐 파일, 새로 생긴 파일, 없어진 파일을 센다. 바뀐 파일이 있으면 "새로고침" 버튼의 기호가 주황색이 되고 그 수가 붙으며, 버튼에 마우스를 올리면 `분석 뒤 바뀐 파일 N개`와 경로 다섯 개까지(넘으면 `외 k개`)를 말풍선에 적는다. 그래프는 스스로 바뀌지 않고 "새로고침"을 눌렀을 때 바뀐다. 새로고침은 열어 둔 언어 서버 세션에서 바뀐 파일과 그 파일에 딸린 지점만 다시 묻고, 분석하는 동안에는 앞의 그래프를 그대로 쓰며 버튼에 도는 원과 단계 이름을 그린다. 다시 분석하지 못하면 앞의 그래프를 둔 채 버튼 아래에 까닭을 적는다.

## 경로 찾기와 경로 고정

경로 탐색 창의 출발 칸과 도착 칸이 차면 출발에서 도착까지 호출을 따라가는 경로를 짧은 것부터 다섯 개까지 찾아 숫자 버튼으로 나열한다. 숫자 아래에는 단계 수를, 버튼의 말풍선에는 단계 수와 거치는 파일 수를 적고, 여섯째 경로가 있으면 "경로가 더 있다"고 적는다. 정보 패널 머리 줄의 `출발로`·`도착으로` 버튼은 창을 편 동안 지금 보이는 파일·클래스·함수를 그 칸에 넣는다.

- **읽는 순서**: 경로를 찾거나 번호를 바꾸면 정보 패널과 단계 목록의 지금 단계가 출발 노드가 되고, 화면은 경로 전체가 들어가면 경로 전체를, 들어가지 않으면 출발 노드와 다음 걸음의 노드를 보인다. 단계 목록의 행을 차례로 누르면 단계마다 그 노드와 다음 걸음의 노드가 보이게 화면이 옮겨지고, 이미 보이는 노드면 화면이 그대로다. 경로 위 노드를 그래프, 파일트리, `Mod+P` 검색으로 골라도 같은 규칙으로 옮겨진다. 단계 목록은 여섯 행 반까지 그리고 넘는 행은 목록 안에서 스크롤하며, 지금 단계의 행이 늘 목록 안에 보인다.
- **경로 전체**: `경로 전체 보기`와 "화면 맞춤"은 확대 비율을 줄여 경로 위 노드를 모두 보이고, 미니맵은 경로의 걸음을 선으로 잇고 출발 노드를 빈 원, 도착 노드를 채운 원으로 그린다.
- **따라가는 선**: 실행 선(호출, 생성)과 이음 두 가지다. 생성자 이음은 클래스에서 그 클래스의 `__init__`·`__post_init__`·`__new__`로 가고, 오버라이드 이음은 부모 메서드에서 그 메서드를 오버라이드한 자식 메서드로 간다. 사용 선(import, 전달, 타입)과 상속 선은 따라가지 않고, 토글로 숨긴 테스트 코드와 외부 노드는 거치지 않는다.
- **끝점**: 함수·메서드는 그 노드 하나, 클래스·파일은 그 안에 든 함수 전체다. 폴더는 끝점으로 고르지 않는다.
- **강조**: 고른 번호의 경로만 본문 잉크 3px 선으로 그리고 이음 구간은 점선으로 그린다. 경로 위 노드는 접힌 파일 상자와 접힌 폴더 안에 있어도 펼쳐 보이고(파일 상자는 경로 위 노드만 그리고 손잡이를 달지 않는다), 경로 밖의 노드와 선은 흐리게 그린다. 출발 노드와 도착 노드에는 `출발`·`도착` 표지가 붙는다.
- **경로 고정**: 경로가 하나라도 나오면 `끄기`를 누를 때까지 그 경로가 고정된다. 고정 중에는 경로 밖의 노드·선·폴더 상자, 파일트리, `Mod+P` 검색, 코드 뷰어의 `Mod`+클릭, 요약의 정의 표기, 뒤로·앞으로, "테스트 코드"·"외부 노드" 토글, 흐름 단계가 선택과 펼침을 바꾸지 않고, 막힌 조작마다 창의 `경로 고정 중 · 경로 밖은 눌리지 않는다` 줄이 잠깐 뒤집힌다. 경로 위의 노드나 선, 단계 목록의 단계를 누르면 강조는 그대로 두고 정보 패널과 탐색 경로 표시, 파일트리의 고른 행이 보이는 노드만 바꾼다. 정보 패널에 열어 둔 `__init__.py`는 고정에 들어갈 때 닫힌다. `Esc`와 그래프 바탕 클릭은 고정을 풀지 않는다.
- **고정 중에 되는 조작**: 화면 이동과 확대, 미니맵, 화면 맞춤, 숫자 버튼, 출발·도착 다시 고르기와 맞바꾸기, 분석 덮개 전환, 범례, 화면 색, 정보 패널의 요약 생성과 코드 범위 설명이다. 창은 접을 수 있고 접어도 고정은 유지되며, 고정 중에는 경로 찾기 버튼을 채워 그린다.
- **경로 없음**: 경로가 없으면 "실행 선으로 이어지는 경로가 없다" 아래에 출발에서 닿는 함수 수와 그 안의 미확인 호출 수를 적고, 반대 방향에 경로가 있으면 맞바꾸기 버튼을 보인다. 이때는 고정이 아니다.

## 분석 덮개

필터 창의 "분석 덮개"에서 덮개 하나를 켠다. 순환 묶음이 있는 레포는 순환 덮개를 켠 채로, 없는 레포는 덮개 없이 연다. 순환 덮개는 켜고 꺼도 상자의 위치가 바뀌지 않는다. 미사용 덮개는 펼친 파일 상자의 손잡이에 든 후보를 꺼내 그리므로 그 상자의 배치가 바뀐다. 켠 덮개는 다음에 열 때 유지하지 않는다. 덮개를 켜고 아무것도 고르지 않았으면 정보 패널이 그 덮개의 결과 목록을 보이고, 목록의 행을 누르면 그 노드를 고른다.

- **순환 의존**: 서로를 import해 돌아오는 파일의 묶음을 찾는다. 함수 안에서 하는 import와 폴더 단위로만 돌아오는 관계는 세지 않는다. 묶음에 든 파일 상자와 그 파일을 품은 접힌 폴더 상자는 덮개와 관계없이 이름표 앞에 순환 아이콘을 달고, 덮개를 켜면 묶음 안의 import 선을 빨간색으로 그린다. 덮개를 켠 동안 변경 표시는 색을 빼고 글자만 남긴다.
- **미사용 후보**: 들어오는 실행·사용 선이 없는 함수·메서드·클래스를 점선 테두리로 흐리게 그린다. 접힌 파일 상자와 접힌 폴더 상자 아래에는 안에 든 후보 수를 `미사용 후보 3`으로 적는다. 테스트 코드가 부르는 정의는 후보가 아니다. 진입점, 데코레이터가 붙은 정의, 이중 밑줄 이름, 상속되는 클래스, 오버라이드로 이어진 메서드 가운데 하나라도 쓰이는 묶음, 외부 클래스를 상속한 클래스의 메서드, 미확인 호출이 같은 이름을 부르는 정의, 이름이 문자열 상수로 적힌 정의, 점 경로가 설정 파일(`.yaml`·`.yml`·`.toml`·`.json`·`.cfg`·`.ini`)에 적힌 정의는 후보에서 뺀다.

경로 고정과 덮개는 함께 켤 수 있다. 고정 중에는 경로가 먼저 읽히도록 순환 선을 색만 남긴 채 흐리게 그리고, 경로 위의 미사용 후보는 점선 테두리만 받는다.

## LLM 요약

정보 패널의 LLM 요약 칸은 고른 파일·클래스·함수의 설명을 요지, 하는 일, 앞뒤 흐름 세 부분으로 보여 준다. 요지는 굵고 크게, 구역 제목은 굵게 그리고, 백틱으로 감싼 식별자와 `파일 경로::정의 이름` 표기는 옅은 바탕의 등폭 글자(코드 칩)로 그린다. 그래프에 있는 정의의 표기는 글자가 파란색인 칩이고 누르면 그 노드를 고른다. 목록 기호로 시작하는 줄은 목록으로, `**`로 감싼 글은 굵게, 코드 울타리 사이의 줄은 코드 블록으로 그린다. 코드 범위 설명 창도 같은 방식으로 그린다. 코드 뷰어가 함께 열려 있으면 요약 칸은 처음에 패널 높이의 4분의 1까지만 쓰고 넘치는 글은 칸 안에서 스크롤한다. 요약 칸과 코드 뷰어 사이의 경계선을 끌어 정한 높이는 다음에 열 때도 유지한다. 설명은 이 컴퓨터에 설치된 Claude Code CLI를 `claude -p`로 불러 만들고, Claude Code에 로그인한 구독 계정을 쓰므로 API 키가 필요 없다.

1. Claude Code CLI를 설치한다(npm으로는 `npm install -g @anthropic-ai/claude-code`). code-atlas는 `claude` 실행 파일을 `PATH`와 `~/.local/bin/claude`에서 찾는다.
2. 터미널에서 `claude auth login`을 실행해 Claude 구독 계정으로 로그인한다.
3. `claude auth status`가 `"loggedIn": true`를 출력하는지 확인한다.
4. code-atlas를 실행해 노드를 고르고 요약 칸의 "요약 생성"을 누른다.

요약은 레포를 열 때 만들지 않고 "요약 생성"을 누를 때 그 노드 하나만 만든다. 필터 창의 "자동 요약" 토글(기본 꺼짐)을 켜면 노드를 고른 채 잠시 머물 때 만든다. 요약 하나가 `claude -p` 호출 한 번이고 구독 사용량을 쓴다. 요약을 만드는 동안 다른 노드를 고르거나 폴더를 접어도 요청은 끝까지 가고, 만드는 중인 노드의 왼쪽 위에는 도는 원이 붙는다. 그 노드가 접혀 보이지 않으면 그 노드를 품은 파일 상자나 접힌 폴더 상자에 붙는다. 호출할 때 고른 노드의 코드와, 분석 결과에서 모은 앞뒤 흐름(그 노드를 호출하는 코드 줄, 그 노드가 호출하는 함수의 시그니처와 문서 문자열, 데이터 클래스 필드, 파일의 문서 문자열)을 Claude에 보낸다.

- **모델**: `sonnet`. 응답이 120초 안에 없으면 요약 칸에 그 사실을 적는다.
- **캐시**: `~/.cache/code-atlas/summaries.db`. 코드, 앞뒤 흐름, 서술 규약 문서, 모델 가운데 하나가 바뀌기 전까지 다시 만들지 않는다. "다시 생성"을 누르면 캐시에 있어도 새로 만든다.
- **바뀌기 전에 만든 요약**: 요약을 만든 뒤 코드나 앞뒤 흐름, 서술 규약 문서가 바뀐 노드는 가장 최근에 만든 요약을 흐리게 보이고 "코드나 앞뒤 흐름이 바뀌기 전에 만든 요약"이라고 적는다. "다시 생성"을 누르거나 "자동 요약"을 켜 두면 새로 만든다.
- **서술 규약 문서**: `--style-guide <경로>` 옵션이나 환경 변수 `CODE_ATLAS_STYLE_GUIDE`로 문체를 정한 문서를 주면 그 문서 전문을 시스템 프롬프트에 넣는다. 문서는 UTF-8이고 100KB 이하여야 한다. 주지 않으면 내장한 짧은 한국어 서술 지침을 쓴다.
- **정의 표기**: 설명은 레포 안의 함수·메서드·클래스를 `{파일 경로}::{정의 이름}`으로 적고(`arbiter.py::arbiter_sync`), 그 표기를 누르면 그래프가 그 노드를 고른다.

코드 뷰어에서 줄 범위를 끌어 고르면 고른 끝에 "요약 생성" 버튼이 뜬다. 누르면 그 범위 아래에 뜨는 창에 그 범위의 코드가 실행되는 순서대로 쓴 설명을 만든다. 호출할 때 고른 범위의 코드와 그 범위가 든 함수·클래스의 전체 코드, 시그니처, 앞뒤 흐름을 Claude에 보낸다.

- **표지**: 설명이 있는 범위는 시작 줄 왼쪽에 말풍선 표지가 붙는다. 창의 `–`를 누르면 표지로 접히고 표지를 누르면 다시 열린다. "지우기"는 그 설명을 지운다.
- **저장**: 설명은 레포 경로, 파일 경로, 줄 범위마다 하나씩 `~/.cache/code-atlas/summaries.db`에 남고 레포를 다시 열면 표지로 다시 보인다. 설명을 만든 뒤 그 줄 범위의 코드가 바뀌었으면 표지와 본문을 흐리게 그리고 "코드가 바뀌기 전에 만든 설명"이라고 적는다.

`claude`가 없거나 로그인돼 있지 않으면, 또는 서술 규약 문서를 읽지 못하면 요약 칸에 그 까닭을 적고 나머지 기능은 그대로 동작한다.

## 변경 표시

대상 레포가 git 저장소면 마지막 커밋(`HEAD`) 뒤에 수정하거나 추가한 파일과 함수를 그래프와 파일트리에 표시한다. 수정은 주황 `M`, 추가(스테이징한 새 파일과 추적하지 않는 파일)는 파랑 `A`이고, 지워진 파일은 파일트리 아래 목록에 적는다. 화면은 15초마다, 그리고 창이 포커스를 받을 때 변경 내용을 다시 읽는다. 필터 창의 레포 정보에 현재 브랜치 이름을 적는다.

대상 레포에는 읽기 전용 git 명령(`status`, `diff`, `rev-parse`, `symbolic-ref`)만 부르고, 인덱스를 다시 쓰지 않으며, 원격에 접속하지 않는다. git 저장소가 아니면 변경 표시 없이 나머지 기능이 동작한다.

## 알려진 한계

- **Python 전용**: `.py` 파일만 분석한다. Windows에서는 확인하지 않았다.
- **큰 라이브러리 폴더**: 파일이 수백 개인 폴더는 첫 분석이 오래 걸린다. Apple M1에서 `site-packages`의 networkx 폴더(파일 580개, 정의 요청 6만 개)는 6~8분이 걸리고 응답 없음이 16~20개 남으며, mlflow 폴더(1,033개)는 10분 안에 끝나지 않는다. sympy(1,532개)와 torch(2,141개) 폴더는 각각 5분과 28분에 중단해 끝나는지 확인하지 못했다. 한 번 분석을 끝낸 레포는 캐시로 열린다(networkx 3초). 상자와 선이 많은 화면은 선과 노드 위에서 커서를 움직일 때 끊긴다(mlflow에서 정의 249개인 파일을 고른 화면은 상자 324개, 선 1,478개이고 커서를 움직이는 동안 프레임 간격이 80~180ms로 늘어난다). 화면을 끌어 옮기는 동안에는 선과 노드의 hover를 받지 않아 프레임 간격이 17ms다.
- **응답 없음**: 언어 서버가 어느 요청에도 10초 동안 답하지 않으면 기다리던 요청을 취소하고 한 번 다시 묻는다. 다시 물어도 10초 안에 답이 없는 지점은 미확인으로 남고 `응답 없음 N`으로 센다. 요청 하나가 10초 넘게 걸리면 그 뒤에서 차례를 기다리던 요청도 함께 응답 없음이 된다. 그 지점의 번호도 캐시에 들어가므로 캐시로 다시 열어도 같은 수를 적고, 그 지점은 그 파일이 바뀌거나 다시 묻는 범위에 들 때와 `--no-cache`로 다시 분석할 때 다시 묻는다.
- **열어 둔 채 고친 코드**: 그래프의 노드와 줄 범위, 코드 뷰어와 요약의 본문은 마지막으로 분석한 값이다. 그 뒤 바뀐 파일은 "새로고침" 버튼에 색과 수로 표시하고 스스로 다시 분석하지 않는다. "새로고침"을 누르면 보기 설정과 선택, 펼친 폴더도 처음 연 상태로 돌아간다. 다시 분석하는 동안 고친 파일의 hover와 정의 이동은 줄이 어긋날 수 있다.
- **여러 탭**: 같은 서버를 탭 두 개로 열고 한쪽에서 새로고침하면 다른 탭도 다음 상태 확인 때 새 그래프로 다시 그려지고 선택과 펼침이 처음 연 상태가 된다. 서버가 내려가도 화면에 연결이 끊겼다는 표시는 없다.
- **동적 호출**: `getattr(obj, name)()`이나 타입 힌트 없는 인자의 메서드 호출처럼 정적 분석으로 대상을 확인하지 못한 호출은 선으로 그리지 않고 정보 패널 머리 줄의 `미확인 호출 N곳`에 수로 적는다.
- **경로 없음이 도달하지 않음을 보장하지 않는다**: 경로 찾기는 그린 선만 따라가므로 미확인 호출을 거쳐야 닿는 함수로는 경로를 찾지 못한다. 경로 없음 문구가 출발에서 닿는 함수 안의 미확인 호출 수를 함께 적는다.
- **미사용 후보는 후보다**: 판정은 정적 분석이 그린 선과 이름 대조에 기대므로, 동적으로만 불리는 정의가 후보로 남거나 이름이 우연히 문자열과 같은 미사용 정의가 후보에서 빠진다. 외부 부모 클래스에서 물려받은 메서드로만 쓰이는 클래스도 후보로 남는다. 지우기 전에 코드를 읽어 확인한다.
- **순환 묶음의 두 파일 사이에 호출이 있을 때**: 두 파일 상자 사이의 선은 import와 호출을 합친 집계 선 하나이므로 순환 덮개가 그 선 전체를 빨간색으로 그린다.
- **선이 상자나 글자 위를 지나는 곳**: 함수 안 import 선은 출발 상자 아래로 곧장 내려가므로 같은 열에서 그 아래에 있는 상자를 지난다. 도착 노드 앞에 적는 합계는 그 노드에서 같은 변으로 나가는 선과 겹칠 수 있다. 한 노드에서 많은 선이 나가면 출발 직후의 구간에서 선이 나란히 붙어 띠처럼 보이고, 그 구간에서는 마우스를 올리거나 눌러 선을 가린다.
- **macOS의 이력 단축키**: `Option+←`·`Option+→`와 `Cmd+[`·`Cmd+]`는 브라우저의 이전·다음 페이지 단축키와 같은 키다. code-atlas가 이 키를 먼저 받아 탐색 이력을 옮기는 동작은 headless Chrome에서만 확인했다. 포커스가 코드 뷰어나 검색 칸에 있으면 `Option+←`·`Option+→`는 낱말 사이를 옮긴다.

## 구성

| 경로 | 역할 |
|---|---|
| `code_atlas/model.py` | 노드·선·지점·분석 결과 자료형. 필드는 HTTP API 계약과 같다 |
| `code_atlas/collect.py` | 분석할 `.py` 파일 수집(`.gitignore`·가상환경 폴더 제외), 소스 루트·테스트 코드 판정, `pyproject.toml`의 진입점 설정, 미사용 판정이 읽는 설정 파일 본문, 경로를 디스크에 적힌 이름으로 맞추기 |
| `code_atlas/extract.py` | 파일마다 `ast`로 정의 노드와 관계 후보 지점(호출·import·이름 사용·데코레이터·타입·상속)을 뽑는다 |
| `code_atlas/lsp.py` | basedpyright 언어 서버 세션 수명, 요청의 시간 제한, 연 파일의 본문 맞추기, UTF-8 바이트·UTF-16 열 변환 |
| `code_atlas/resolve.py` | 언어 서버가 돌려준 정의 위치를 노드 id와 선 종류로 바꾼다 |
| `code_atlas/graph.py` | 노드·선 조립, 패키지 노드, 데이터 클래스·오버라이드·진입점 판정, 해석률 집계 |
| `code_atlas/analyze.py` | 수집부터 그래프 조립, 미사용 후보 판정까지 차례로 부르는 분석 진입점 `refresh`. 캐시나 앞의 결과에서 시작해 다시 물을 지점을 고르고 단계와 진행 수를 알린다. 인터프리터 확인과 분석 뒤 바뀐 파일 판정도 맡는다 |
| `code_atlas/cache.py` | 파일의 추출 결과와 지점의 판정을 레포마다 SQLite 파일 하나(`~/.cache/code-atlas/analysis-*.db`)에 담고 환경 지문을 계산한다 |
| `code_atlas/runner.py` | 분석 태스크 하나의 수명과 진행 상태, 언어 서버 세션, 분석 캐시를 맡는다 |
| `code_atlas/unused.py` | 분석 결과에서 들어오는 실행·사용 선이 없는 정의를 찾고 제외 규칙 일곱 개를 적용해 미사용 후보를 낸다 |

## 개발

```bash
.venv/bin/pip install -e '.[dev]'
.venv/bin/pytest
```

`tests/test_lsp.py`·`tests/test_graph.py`·`tests/test_refresh.py`·`tests/test_runner.py`·`tests/test_api.py`·`tests/test_cli.py`·`tests/test_unused.py`·`tests/test_cycles.py`는 code-atlas 가상환경의 basedpyright를 실제로 띄운다. LLM 요약 테스트는 가짜 `claude`를 쓰고 실제 CLI를 부르지 않는다. 테스트는 고정 레포를 임시 디렉토리에 복사해 돌린다. git에 담을 수 없는 무시 대상 파일과 가상환경 폴더는 `tests/conftest.py`가 복사본에 만든다. 분석 캐시는 임시 폴더에 두므로 테스트는 `~/.cache/code-atlas`에 쓰지 않는다.

화면을 고칠 때는 백엔드를 띄운 채 `frontend/`에서 `npm run dev`를 실행한다. Vite 개발 서버가 `/api`를 `localhost:8766`으로 넘긴다. `npm run typecheck`로 타입을 검사하고, `npm test`로 화면 없이 계산하는 모듈을 고정 그래프에서 확인한다. 대상은 저장소와 경로 고정, 덮개, 변경 내용, 분석 상태, 요약과 코드 범위 설명의 요청(`state/`), 보이는 노드와 펼침 단계·흐름·그릴 선·열 배정·배치·선 경로와 줄기·숫자의 위치·커서 밑의 선·배치 움직임·화면 이동·함수 시점 뷰·경로·순환 묶음·덮개 표시·배지 말풍선의 글(`graph/`), 경로 탐색 창의 글(`route/words`), 기본값과 다른 보기 설정(`nav/settings`), 정보 패널 사각형·연 파일·설명 나누기(`panel/`), 검색 색인(`search/`), 파일트리 행(`tree/`)이다.

화면은 `frontend/`에서 화면 시나리오 스크립트로 확인한다.

```bash
node scripts/shots.mjs [주소] [--cycle-url 주소] [--reload-url 주소] [--wide-url 주소] [--only 이름,이름] [--with-summary]
```

떠 있는 서버의 주소를 받고(기본 `http://127.0.0.1:8766`) 서버를 띄우지 않는다. 시나리오마다 새 브라우저 컨텍스트에서 조작하고 확인 항목을 `통과`·`실패`·`건너뜀`과 함께 한 줄씩 출력한다. 대상 레포에 입력이 없어 볼 수 없는 확인 항목은 `건너뜀`이고 실패로 세지 않는다. 실패한 확인 항목이나 페이지 오류·콘솔 오류가 있으면 종료 코드 1로 끝난다.

- **시나리오**: `open`, `file`, `function`, `body`, `panel`, `code-scope`, `hover`, `edge`, `badge-tip`, `minimap`, `region`, `folder`, `folder-select`, `init-file`, `toolbar`, `callview`, `search`, `zoom`, `labels`, `external`, `dark`, `tree`, `tree-search`, `changes`, `zoom-keep`, `summary-panel`, `split`, `summary-busy`, `summary-stale`, `explain`, `summary-ask`, `summary-ref`, `summary`와 경로·덮개 시나리오 `finder-open`, `finder-search`, `finder-path`, `finder-folder`, `finder-step`, `finder-none`, `finder-pin`, `finder-change`, `finder-ends`, `overlay-menu`, `reload`, `unused`, `finder-overlay`, `overlay-dark`, `cycles`, `cycles-change`, `cycles-pin`, 처음 화면·펼침·합류·분석 상태 시나리오 `start`, `arranging`, `node-hover`, `merge`, `merge-hover`, `merge-click`, `merge-select`, `merge-pin`, `badge`, `pack-file`, `pack-flow`, `pack-folder`, `pack-find`, `pack-pin`, `pack-overlay`, `pack-history`, `pack-toggle`, `lanes`, `numbers`, `overlap`, `progress`, `progress-failed`, `stale` 73개다. `--only`에 이름을 쉼표로 이어 주면 그 시나리오만 돌고, 모르는 이름을 주면 고를 이름을 적고 종료 코드 2로 끝난다.
- **기대값**: 노드 이름은 sync-engine을 연 서버가 기준이고, 노드 수·선 수·줄 범위는 서버 응답에서 읽는다. 경로 수와 단계 수, 순환 묶음, 미사용 후보 수, 파일 상자의 펼침 단계에 그리는 정의, 줄기와 들어오는 합계는 `/api/graph`와 `/api/unused` 응답에서 화면과 같은 규칙으로 계산한다. 폴더 안의 파일 상자를 보는 시나리오는 소스 루트 바로 아래의 접힌 폴더를 먼저 펼친다.
- **순환 시나리오**: `cycles`, `cycles-change`, `cycles-pin`은 `tests/fixtures/cycle_repo`를 연 서버의 주소를 `--cycle-url`로 받았을 때만 돌고, 받지 않으면 건너뜀으로 출력한다.
- **`reload`, `stale`**: 대상 레포의 파일을 고쳤다가 되돌리므로 `tests/fixtures/sample_repo`를 임시 폴더로 복사해 연 서버의 주소를 `--reload-url`로 받았을 때만 돈다.
- **`lanes`, `numbers`**: 폴더가 여러 겹인 레포를 연 서버의 주소를 `--wide-url`로 받으면 폴더 세 개를 펼친 화면도 본다.
- **`progress`, `progress-failed`**: `/api/status`의 응답을 바꿔 분석 중인 화면과 분석하지 못한 화면을 본다. 서버의 분석은 건드리지 않는다.
- **`finder-pin`**: 경로 고정 중에 경로 밖 파일 상자, 접힌 폴더 상자, 그래프 바탕, `Esc`, 더블클릭, 파일트리, `Mod+P`, 코드 뷰어의 `Mod`+클릭, 요약의 정의 표기, `Alt+←`, 토글과 흐름 단계를 실제로 눌러 강조가 그대로인지 본다.
- **`summary`**: 실제로 요약 하나를 만들어 Claude Code 구독 사용량을 쓰므로 `--only`로 지정하거나 `--with-summary`를 줬을 때만 돈다. 나머지 72개 시나리오는 요약을 만드는 요청을 서버로 보내지 않고, Claude Code CLI의 설치와 로그인 상태를 전제하지 않는다.
- **`changes`**: 대상 레포에서 `git status`·`git diff`를 직접 읽어 화면과 비교하므로 서버와 같은 컴퓨터에서 돌린다. 수정한 `.py` 파일이 없는 레포에서는 확인 항목을 건너뛴다.
- **스크린샷**: `~/data/code-atlas/screenshots/s2-{이름}.png`(1700×1000, 배율 2)에 남기고, 경로·덮개 시나리오는 `s3-{이름}.png`에, 처음 화면·펼침·합류·분석 상태 시나리오는 `s4-{이름}.png`에 남긴다. `toolbar`는 창 폭 1700·1440·1280·1160·980·900·720px마다 `s2-toolbar-{폭}.png`를, `finder-open`과 `overlay-menu`는 창 폭 1700·1280·980·720px마다 `s3-{이름}-{폭}.png`를 더 남긴다.
- **브라우저**: Playwright가 받은 chromium과 다른 실행 파일을 쓰려면 환경 변수 `CHROMIUM_PATH`에 경로를 넣는다.
- **캐시를 쓰지 않는 실행**: 시나리오용 서버가 `~/.cache/code-atlas`에 분석 캐시를 남기지 않게 하려면 서버를 `HOME`을 임시 폴더로 바꿔 띄운다.

성능은 두 스크립트로 잰다. 둘 다 대상 레포에 파일을 쓰지 않는다.

```bash
.venv/bin/python scripts/measure_analysis.py <레포> [--python PATH] [--runs 3] [--no-cache] [--cache-dir 폴더] [--dump 결과.json] [--compare 결과.json]
cd frontend && node scripts/perf.mjs <주소> [--expand 폴더id] [--pick 검색어] [--shot 경로 접두어]
```

- **`measure_analysis.py`**: 실행마다 분석을 한 번 돌려 전체 시간과 단계별 시간(파일 수집, 구조 추출, 환경 지문, 언어 서버 기동과 준비 확인, 정의 요청, 그래프 조립, 미사용 판정, 캐시 쓰기), 정의 요청 수, 응답 없음 수를 한 줄에 실행 하나씩 JSONL로 출력한다. `--cache-dir`은 분석 캐시를 둘 폴더이고, `--dump`는 마지막 실행의 분석 결과를 `code-atlas analyze --json`과 같은 JSON으로 쓰며, `--compare`는 그 JSON과 노드·선·지점별 판정을 견줘 다른 수를 적는다.
- **`perf.mjs`**: 떠 있는 서버의 화면을 열어 첫 상자가 그려지기까지의 시간, 처음 화면·`--expand`로 펼친 화면·`--pick`으로 고른 화면마다 조작부터 화면이 멈추기까지의 시간, ELK worker의 응답 시간, 느린 배치 표시가 떴는지, 보이는 상자·선·줄기의 수, 화면을 끌어 옮길 때와 휠로 확대할 때의 프레임 간격(p50·p95, fps)을 JSON 한 줄로 출력한다.
